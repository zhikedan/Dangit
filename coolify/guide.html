一键部署 · Coolify 部署指南

COOLIFY v4 · WSL2 UBUNTU 24.04 · LOCAL ONLY

📌 这条链路是怎么跑起来的

网页版里的「🚀 一键部署」不是把代码拷到某个文件夹，而是调用本机 Coolify 的 REST API：

你填仓库 + 访问地址
   │
   ▼
html/server.js  →  coolify.js（后端代理，Token 不出机器）
   │  POST /api/v1/applications/public
   │  PATCH /api/v1/applications/{uuid}   ← 写域名 / 端口映射
   │  GET  /api/v1/deploy?uuid=...
   ▼
Coolify（WSL2 里的 Docker）→ 拉代码 → 构建镜像 → 起容器
   ▼
Traefik（80 端口）→ http://你的地址.localhost
🔑 创建 API Token 🎯 三步完成部署 🔌 两种访问方式 🩺 常见问题 ⌨️ 常用命令 📁 相关文件

1开启 API 并创建 Token（只需一次）

⚠️ 两个开关都要开：Coolify 默认关闭 API 访问，只建 Token 是调不通的（会提示 “API access is turned off”）。
  1. 浏览器打开 http://localhost:8000 并登录 Coolify。
  2. 进入 设置（Settings）→ 高级（Advanced），找到 API and MCP 区块，把 API access 从「已禁用」改成 「已启用」，点右下角 保存更改。
  3. 左下角点头像 → 密钥与令牌（Keys & Tokens） → API 令牌 标签页 → 创建；权限选 Root（部署要写权限，只读 Token 会在建应用时 403）。
  4. 复制生成的 Token（只显示一次），回到网页版「🚀 一键部署」→ 点 🔑 配置 Token 粘贴保存。
✅ 保存时会立刻校验：能读到项目列表就算成功，Token 只写进本机 html/config.json，不会回传给浏览器。
⚠️ 不要把这个 Token 发到公开仓库或截图里；需要重置时在同一个页面删除旧 Token 再建一个即可。

2三步完成部署

  1. 填项目：输入 owner/repo 或完整网址（GitHub / Gitee 都行）。输入框失焦后会自动解析，显示星标、语言、默认分支，并预填分支 / 构建方式 / 容器端口。
  2. 选目标地址：自动域名（项目名.localhost）/ 本机端口（如 localhost:8080）/ 自定义域名，见下一节。
  3. 点开始部署：弹窗里会实时滚构建日志；成功后直接给出「打开应用」和「打开 Coolify 项目」两个按钮。

高级选项什么时候用

选项什么时候需要改
分支要部署的不是默认分支（如 dev / release）
构建方式仓库里有 Dockerfile 选 Dockerfile；多服务选 Docker Compose；纯静态选 Static
容器端口构建日志里报端口不对，或应用实际监听 5000 / 8000 等非 3000 端口

3两种访问方式，怎么选

方式访问地址适合
🌐 自动域名http://项目名.localhost最省事，Chrome / Edge 会把 *.localhost 直接解析到本机
🔌 本机端口http://localhost:8080端口固定、要用别的工具连；注意别和本程序（5215）、Coolify（8000）冲突
✏️ 自定义域名如 http://app.127.0.0.1.nip.io要模拟真实域名、或者局域网内其他设备访问
💡 Ports Exposes 不是浏览器端口：它指容器内部监听端口，Traefik 再把它转到 80。浏览器访问的永远是上面选的地址。
⚠️ 如果 *.localhost 打不开，用管理员权限在 C:\Windows\System32\drivers\etc\hosts 加一行：127.0.0.1 项目名.localhost。

4常见问题

弹窗里显示「Coolify 未启动」

双击 E:\pc\桌面\wsl2\启动Coolify.cmd，等 30 秒再点一次状态刷新（关闭弹窗重开即可）。仍然不行就执行 wsl --shutdown 后重来。

Token 保存时报 401 / 权限不足

Token 复制不完整，或创建时没给写权限。删掉重建一个 Root 权限的 Token。

构建成功但打开是 502

应用没监听 0.0.0.0，或容器端口填错。Node 项目要写 app.listen(process.env.PORT || 3000,'0.0.0.0')；再检查「容器端口」是否等于应用真实端口。

构建卡在拉镜像 / 很慢

Coolify 已配置 docker.1ms.run 镜像加速；若某镜像不在加速站，构建会慢，可在面板 Deployment 日志里确认卡在哪一层。

部署失败怎么排查

弹窗日志只给阶段信息，详细构建日志看 Coolify 面板 → 项目 → 应用 → Deployments。也可在网页版「高级选项」里改分支 / 构建方式重试。

5常用命令（Windows PowerShell）

# 进 Ubuntu
wsl -d Ubuntu-24.04

# 看容器
wsl -d Ubuntu-24.04 -u root -- docker ps -a

# 看 Coolify 日志
wsl -d Ubuntu-24.04 -u root -- docker logs --tail 100 coolify

# 重启 Coolify
wsl -d Ubuntu-24.04 -u root -- docker restart coolify

# 整套停 / 起
wsl -d Ubuntu-24.04 -u root -- bash -lc "cd /data/coolify/source && docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml down"
wsl -d Ubuntu-24.04 -u root -- bash -lc "cd /data/coolify/source && REGISTRY_URL=docker.1ms.run LATEST_IMAGE=latest docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml up -d"
⚠️ 不要执行 docker system prune -a，会删掉 Coolify 正在用的镜像；不要删除面板里的 localhost 服务器。

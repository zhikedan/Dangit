LOCAL PATH DEPLOY · AUTO BUILD

📌 它做了什么

你只需要给两样东西：项目名称/仓库网址 和 本地目标路径。其余全部自动：

解析项目 → 校验路径 → 环境检测 → 获取源码 → 安装依赖 → 构建
        → 产物落位（自动备份） → 完整性校验 → 生成启动脚本 → 输出结果
✅ 全程在系统临时目录里构建，只有全部成功才写入目标路径；中途失败不会破坏你已有的文件。

2目标路径的规则

情况处理
E:\pc\桌面\github\xxt\githubxiangmu\githubbushu✅ 视为父目录：自动在其中新建以项目名命名的文件夹（这里是 …\githubbushu\HivisionIDPhotos），互不干扰
E:/pc/桌面/github（斜杠写法）✅ 两种分隔符等价，自动归一化
父目录不存在✅ 自动逐级创建
项目子目录已存在且非空先改名备份为 xxx.bak-时间戳 再写入；也可选「直接写入目标地址」或「合并覆盖」
目录被占用（资源管理器 / 编辑器 / 杀软）自动重试 3 次；仍失败则改为就地合并覆盖（不删除已有文件），不会再直接报错中断
xxt\abc（相对路径）❌ 明确拒绝：必须是带盘符的绝对路径
C:\Windows\...、盘符根目录、Program Files❌ 明确拒绝：系统目录不允许
本程序自身目录❌ 明确拒绝：避免覆盖程序文件
盘符不存在 / 无写权限❌ 立即提示具体原因，不会开始下载
💡 不确定路径？点输入框右侧 📁 浏览，用系统文件夹选择框挑一个父目录即可。

3自动处理了哪些常见异常

异常自动处理
没有安装 Git直接改用 ZIP 下载源码
Git 拉取被中断（SSL / 代理 502）自动改用 ZIP 下载重试
默认分支不是 main依次尝试 main、master，都不行再按默认分支取
npm 官方源很慢优先走国内镜像 registry.npmmirror.com，失败再回退官方源
pip 很慢 / 镜像缺包先做依赖预检（查 PyPI 上被固定版本有没有适配当前 Python 的轮子，2 秒级）；再依次尝试清华 → 阿里云 → PyPI 官方源；Python 依赖装在项目内 vendor/，不动系统环境
依赖需要编译（缺 pg_config / VC++）识别为构建类错误，立刻停止换源重试，直接提示缺什么工具
npm 镜像缺版本（ETARGET）依赖预检：装之前先查镜像是否有项目固定的版本（含 ^/~ 范围），缺则直接切官方源，省掉一次失败重试
下载很慢、看起来像卡住npm 加 --loglevel=http 持续输出请求日志；每 30 秒心跳提示；静默判定放宽到 10 分钟（大仓库解析阶段 npm 默认几乎不打印）
要下载的东西占 C 盘临时目录与 pip/npm 缓存统一放在 E:\deploy_cache（跟随程序所在盘），不占用系统盘
取消部署立即生效：马上终止子进程、停止写盘，状态变为「已取消」（不算失败）
项目没有 build 脚本跳过构建，按静态/可运行源码直接部署
静态站点端口 8080 被占用启动脚本自动顺延到 8081、8082…
构建失败回传最后几行真实错误，并标明失败阶段

4部署完成后你会得到

  • 目标目录里的可运行内容：静态站点是成品文件；Node 服务端项目是「源码 + node_modules」，可直接启动
  • 启动.bat：双击即可运行（静态站点会自动打开浏览器；Python / Node 首次运行会自动装依赖；项目自带 docker-compose 时优先用 Docker，没装 Docker 才退回本地运行）
  • 使用说明.txt：中文说明（判定、建议 Python 版本、启动方式、常见问题）
  • 部署信息.json：仓库、分支、类型、文件数、大小、环境版本、耗时等元信息
  • 界面上的结果卡：文件数、体积、耗时、备份位置、启动命令、免部署 / 需要部署 判定，可一键「打开目录 / 启动项目 / 复制路径 / 补装依赖」
  • 历史记录：data/deploy_history.json（界面「🕘 部署记录」可查）
⚠️ 启动.bat 一律是纯英文（ASCII）：Windows 批处理按系统 ANSI 代码页（中文系统是 GBK/936）解析文件，如果里面写 UTF-8 中文，cmd 会把它拆成非法命令，报「'xx' 不是内部或外部命令」。中文说明因此放在「使用说明.txt」里。
🧩 依赖没装齐时（多见于 Python 版本不匹配），结果卡上会出现「🧩 补装依赖」按钮，点一下即可在已部署目录里重装依赖，并自动重写启动脚本。
⚠️ 纯库项目（如 expressjs/express 本体）没有 start/build 脚本，部署后只能作为源码使用；要跑起来请换成带 demo 的应用仓库。

5失败时怎么读懂提示

每条失败都会带「阶段」和「原因」，例如：

[校验路径] 路径必须是绝对路径（带盘符），例如 E:\pc\桌面\github\xxt，不支持相对路径
[获取源码] 源码获取失败：下载失败（HTTP 404）        → 仓库不存在或分支不对
[安装依赖] 依赖安装失败：npm ERR! network …          → 网络问题，检查代理
[构建项目] 构建失败（npm run build）：…              → 看最后几行真实报错

对应处理：改路径 / 换仓库地址 / 开代理或加速器 / 在本地先手动跑一次构建看完整日志。

6问题总结（出错时自动生成）

什么时候自动生成：部署过程中一旦出现错误（哪怕后来靠 ZIP 兜底成功了），或最终部署失败，结束时会自动汇总本次全部问题，生成一份“问题总结”。

按钮在哪：「🚀 一键部署」弹窗底部按钮区，「📖 部署说明」的左侧，名为 📋 问题总结。

状态按钮表现
还没部署 / 本次零问题置灰不可点，鼠标悬停提示「本次部署没有发现问题」
有提示（如走了 ZIP 兜底、非空目录已备份、无 start 脚本）可点击，右侧黄色数字徽标显示条数
有错误 / 最终失败可点击，红色数字徽标；失败结果卡里也会出现「📋 查看问题总结」快捷入口

点击后看到什么：

  • 概览：时间、结果、失败阶段、项目与分支、目标路径、类型与策略、耗时
  • 失败原因：自动归类的根因（网络中断 / 仓库不存在 / 无写权限 / 依赖安装 / 构建失败 / 缺少环境…）+ 原始错误信息
  • 处理建议：针对该类问题的可执行步骤（如「开代理后重试」「确认分支名」）
  • 问题清单：按时间列出每条错误/提示，含阶段、说明、建议
  • 已自动处理：本次自动做过的补救（Git→ZIP、分支回退、镜像切换、目录备份…）
  • 环境信息：Node / npm / Git / Python / Go 版本、系统架构、目标盘剩余空间
  • 关键日志：最后 30 条运行日志，便于定位
💾 总结可「复制」到聊天窗口，或「另存为 Markdown」；每次部署的总结同时保存在 data/deploy_issues/（含 latest.json 与同名 .md），便于回溯。

7部署判定：免部署 / 需要部署

部署完成后会额外给出一项判定，写在结果卡、问题总结（概览行「部署判定」）和 部署信息.json 里。

判定典型项目理由与建议
📄 免部署纯静态页 / 文档站；Node、Python、Go 的
库与工具包（无 start/build、无 Web 框架、无 main）		双击 index.html 或按 README 引用即可，不需要常驻服务；要分享再用「▶ 启动」起本地静态服务器
🚀 需要部署带 Dockerfile / Compose；Node 有 start 或 build；
Python 有 Flask/Django/FastAPI/Gradio 或 app.py；Go 有 main 包；PHP		需要构建产物或常驻进程；点「▶ 启动」/ 双击 启动.bat，或用 Coolify 部署
💡 判定只是建议，不影响文件落位：即使判为「免部署」，源码与启动脚本也已经完整放进目标目录。
